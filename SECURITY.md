# Security and privacy

This is a publication candidate. Use only personally controlled, authorized accounts and assets. Do not publish private archives, employer material, secrets, model credentials or hidden datasets. If you discover a vulnerability, contact the maintainer privately via GitHub security advisory (if enabled), not a public issue containing secrets. No designated security address yet.

Standard public Actions runs only fixed trusted test profiles. PRs have read-only contents permission and no configured secrets, no persisted checkout credentials, no `pull_request_target`, no auto-publish, no scheduled campaigns. Review external contributions and changes to tests/verifier/workflows. No self-hosted runner. User-level Python resource limits and ephemeral GitHub VMs do not isolate an untrusted candidate from its verifier. Arbitrary generated code, live model API, signed verifier identity and hardened execution remain disabled/planned. Existing local server is loopback-only, unauthenticated: do not proxy it publicly.

Notebook and ledger checks provide local consistency, not signatures, trusted timestamps or protection from a malicious writer with repository control. All finite verdicts are scoped to known tests; do not promote to universal theorem or complexity bound. Public evidence entries need explicit maintainer review. No tokens in static portal. Review GitHub billing, permissions, branch rules, push protection, dependency security and contributor approval manually. Do not circumvent service limits or use free Actions as an unrestricted compute service.
